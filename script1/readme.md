## 1. Зачем это нужно

При создании **сети региональных сайтов** (`muhomor.spb.ru`, `muhomor.msk.ru`, `muhomor.ekb.ru` и т. д.) на одной CMS поисковые системы (Яндекс, Google) могут **«склеить»** сайты в одну сеть и **пессимизировать** выдачу. Это называется **аффилиат-фильтр** (Яндекс) или **SpamBrain** (Google).

**Как поисковики определяют, что сайты связаны:**

- **Технические футпринты** — одинаковые CSS-классы, HTML-комментарии, структура кода.
- **Инфраструктура** — один IP, один хостинг.
- **Контакты** — одинаковые телефон, email, адрес.
- **Контент** — дублирующиеся тексты, картинки.

**Что решает этот скрипт:**

1. **Заменяет CSS-классы** — `hero-section` → `msk-hero-section`.
2. **Удаляет HTML-комментарии** — `<!-- Hero -->` убирается.
3. **Удаляет CSS-комментарии** — `/* ... */` убирается (кроме `/*! ... */`).
4. **Перемешивает блоки на главной** — Hero всегда первый, остальные в случайном порядке.

**Что НЕ решает (делается вручную):**

- Уникальные тексты для каждого города.
- Уникальные картинки.
- Разные телефоны / email / юрлица.
- Разные хостинги / IP.
- Уникальный домен.

**Комбинированный подход** (скрипт + ручная работа) даёт **80–90% уникализации**.

## 2. Что делает скрипт

**Алгоритм:**

1. **Копирует** папку CMS в новую директорию.
2. **Проходит** по всем `.php`, `.css`, `.js`, `.html`, `.htm` файлам.
3. **Перемешивает** блоки в `index.php` (кроме фиксированного первого).
4. **Заменяет** CSS-классы на уникальные с префиксом.
5. **Удаляет** HTML-комментарии (кроме условных).
6. **Удаляет** CSS-комментарии (кроме `/*! ... */`).
7. **Сохраняет** результат в новую папку.
8. **Пишет лог** в `logs/`.
9. **Пишет JSON-отчёт** в `reports/`.

**Режимы работы:**

- **`safe`** (по умолчанию) — заменяет **только** кастомные классы (содержащие `-` или `__`).
- **`aggressive`** — заменяет **все** классы, кроме `skip_classes`.

**Что НЕ трогается:**

- Tailwind-утилиты (`flex`, `grid`, `text-center`).
- ID-атрибуты (`id="cartSidebar"`).
- `data-*` атрибуты.
- PHP-комментарии (`// ...`, `/* ... */` внутри PHP).
- JavaScript-логика (только селекторы).
- Структура папок.

## 3. Установка

### Требования

- **Python 3.7+**
- **pip**
- **FTP-доступ** к CMS (чтобы скачать исходную папку)

### Установка

```bash
# Клонировать / скачать проект
cd customize-cms

# Установить зависимости
pip install -r requirements.txt
```

### `requirements.txt`

```txt
PyYAML>=6.0
```

**Больше ничего не нужно.** Скрипт использует **стандартную библиотеку Python** и **PyYAML** для чтения конфига.

    - "__pycache__"

    - "*.log"

  path: "./muhomor-msk"           # Куда сохранить результат
  overwrite: false                 # Перезаписывать ли, если папка существует
  backup_before_overwrite: true   # Делать ли резервную копию перед перезаписью

# --- Уникализация классов ---
unique:

## 6. Использование

### Dry-run (безопасный режим — ничего не сохраняет)

```bash
python customize_cms.py --dry-run
```

**Что выведет:**
- Список замен в консоль и в `logs/`.
- **Ничего не сохранит**.

### Запуск с seed (воспроизводимый порядок блоков)

```bash
python customize_cms.py --seed 12345
```

`--seed` — **число** для инициализации `random`. Одинаковый seed → **одинаковый порядок** блоков.

### Запуск без seed (каждый раз новый порядок)

```bash
python customize_cms.py
```

### Другой конфиг (для разных городов)

```bash
python customize_cms.py --config config-msk.yaml
python customize_cms.py --config config-spb.yaml
python customize_cms.py --config config-ekb.yaml
```

### Переопределить префикс

```bash
python customize_cms.py --prefix ekb
```

**Полезно**, если конфиг общий, а префикс меняется.

### Все аргументы

| Аргумент | Что делает | По умолчанию |
|----------|-----------|--------------|
| `--config` | Путь к конфигу | `config.yaml` |
| `--dry-run` | Не сохранять | `false` |
| `--prefix` | Переопределить префикс | из конфига |
| `--seed` | Seed для random | случайный |

## 7. Что заменяется и что нет

### Заменяется

| Что | Пример до | Пример после |
|-----|-----------|--------------|
| **Кастомные классы** | `hero-section` | `msk-hero-section` |
| **BEM-элементы** | `product-card__image` | `msk-product-card__image` |
| **BEM-модификаторы** | `btn-primary` | `msk-btn-primary` |
| **CSS-селекторы** | `.hero-section { }` | `.msk-hero-section { }` |
| **JS-селекторы** | `querySelector('.hero')` | `.msk-hero` |
| **classList** | `classList.add('active')` | `classList.add('msk-active')` |
| **HTML-комментарии** | `<!-- Hero -->` | (удалено) |
| **CSS-комментарии** | `/* ... */` | (удалено) |
| **Порядок блоков** | Hero → Товары → Блог | Hero → Блог → Товары |

### НЕ заменяется

| Что | Пример | Почему |
|-----|--------|--------|
| **Tailwind-утилиты** | `flex`, `grid`, `text-center` | Сломает вёрстку |
| **ID-атрибуты** | `id="cartSidebar"` | Используется в JS |
| **data-атрибуты** | `data-id="5"` | Используется в JS |
| **PHP-комментарии** | `// ...` | Код станет нечитаем |
| **Условные комментарии** | `<!--[if IE]>` | Нужны для старых IE |
| **`/*! ... */`** | Лицензии | Важно сохранять |
| **Градиенты** | `linear-gradient(...)` | Стиль |
| **URL-адреса** | `/uploads/...` | Пути к файлам |

## 9. Возможные проблемы

### Проблема 1 — вёрстка сломалась

**Симптом:** после загрузки новой папки сайт выглядит неправильно.

**Причины:**
- Класс **не заменился** в `.css`, но **заменился** в `.php` (или наоборот).
- Класс **заменён в HTML**, но **не заменён** в JS-селекторе.
- Класс **заменён в CSS**, но **не заменён** в inline-стилях.

**Решение:**
1. Откройте **DevTools → Console** — там будут ошибки.
2. Найдите **проблемный класс**.
3. Добавьте его в **`skip_classes`** в `config.yaml`.
4. **Перезапустите** скрипт.

### Проблема 2 — JavaScript не работает

**Симптом:** кнопки не нажимаются, корзина не открывается.

**Причина:** селектор в JS **не заменился** (например, `document.getElementById('heroSection')` — а `id` мы не трогаем).

**Решение:**
1. Проверьте **DevTools → Console** — ошибки JS.
2. Если проблема в `id` — **не трогаем** (у нас `skip_id_attributes: true`).
3. Если проблема в **CSS-классе внутри JS** — проверьте, что скрипт **не пропустил** его.
4. Если пропустил — **добавьте файл** в `extensions` (например, `.js` уже есть).

### Проблема 3 — скрипт не находит `index.php`

**Симптом:** в логе `shuffle_index_blocks: пропущено`.

**Причина:** комментарии в `index.php` **не совпадают** с `shuffle_blocks` в конфиге.

**Решение:**
1. Откройте `index.php`.
2. Посмотрите **точные комментарии** перед блоками.
3. **Обновите** `shuffle_blocks` в `config.yaml`.
4. Перезапустите.

### Проблема 4 — префикс уже используется

**Симптом:** скрипт **повторно** добавляет префикс (`msk-msk-hero-section`).

**Причина:** вы запустили скрипт **на уже обработанной** папке.

**Решение:** **не запускайте** скрипт на `muhomor-msk`. **Только** на **исходной** `muhomor-spb`.

### Проблема 5 — разные версии Python

**Симптом:** ошибки синтаксиса при запуске.

**Решение:** убедитесь, что **Python 3.7+**:

```bash
python --version
```

Если у вас **Python 2** — используйте `python3`:

```bash
python3 customize_cms.py
```

## 10. Расширение под свои нужды

### Добавить новый блок в перемешивание

**В `config.yaml`:**

```yaml
html:
  shuffle_blocks:
    - "Преимущества"
    - "Новый блок"     # ← добавить
```

**В `index.php`** — блок должен **начинаться с комментария**:

```html
<!-- Новый блок -->
<section>...</section>
```

### Добавить новую папку в исключения

**В `config.yaml`:**

```yaml
source:
  exclude:
    - "tests"          # ← добавить
```

### Уникализировать ID-атрибуты

**Сейчас:** `skip_id_attributes: true` — **не трогает** `id`.

**Если хотите** — можно **включить** обработку `id`:

**В `config.yaml`:**
```yaml
skip_id_attributes: false
```

**В `customize_cms.py`** — добавить функцию `process_id_attributes()`.

**⚠️ Внимание:** это **сломает** JavaScript (`document.getElementById()`), если не обновить **все** JS-файлы.

### Добавить уникализацию для JSON

**Сейчас:** `data/*.json` **не обрабатывается**.

**Можно добавить** в `extensions`:
```yaml
files:
  extensions: [".php", ".css", ".js", ".html", ".json"]
```

**⚠️ Внимание:** в JSON **могут быть** HTML-строки с классами — они **заменятся**. Но **структура** JSON **должна остаться** валидной.
