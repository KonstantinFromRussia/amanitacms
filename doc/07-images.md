# 07. Изображения и WebP

**Проект:** AmanitaCMS · **Версия CMS:** 2.5 · **Актуально на:** 22 ноября 2026

**Демонстрационные сайты:** `muhomor.spb.ru`, `amanitalove.ru`

---

## 1. Обзор

Работа с изображениями построена на **автоматической WebP-конвертации** и **SEO-именах файлов**. Цель — уменьшить вес страниц (PageSpeed) и улучшить индексацию картинок.

- WebP-конвертация при загрузке (`upload.php`).
- Транслитерация кириллицы в SEO-имена.
- Проверка на дубликаты.
- `<picture>` с WebP + fallback на оригинал (`renderPicture()` в PHP, `buildPicture()` в JS).
- SEO-переименование старых картинок (`rename-all-images.php`).
- Batch-WebP-конвертация старых картинок (`batch-webp.php`, исторический).
- Принудительная оптимизация старых картинок (`scripts/optimize-uploads.php`, **11.11.2026**).

## 2. Загрузка изображений (`upload.php`)

### 2.1. Валидация

- **`finfo`** — проверка MIME-типа.
- **`getimagesize()`** — проверка, что это реально изображение (а не переименованный PHP-скрипт).
- **Двойная валидация** — оба метода должны подтвердить.

### 2.2. Транслитерация имени

- Кириллица → латиница, пробелы → дефисы, спецсимволы удаляются.
- **Пример:** `Мухомор красный 100г.jpg` → `muhomor-krasnyy-100g.jpg`.

### 2.3. Проверка на дубликаты

- Если файл с таким именем уже есть — добавляется суффикс (`-1`, `-2`, ...).

### 2.4. WebP-конвертация (актуально на 11.11.2026)

- **WebP создаётся из уменьшенной копии** (макс. 1200px по большей стороне), качество 82.
- **JPG/PNG-оригинал уменьшается** до 1200px (качество 75) и **остаётся как fallback** — для OG-тегов и старых браузеров.
- Если WebP больше оригинала — WebP-копия удаляется.
- Если GD/WebP недоступны — сайт работает на оригиналах (функциональность не страдает).

> ⚠️ **Старое поведение (до 11.11.2026):** WebP создавался из полного оригинала (без уменьшения), JPG-оригинал не сжимался. Заменено на «WebP из уменьшенной копии + сжатый JPG-оригинал».

### 2.5. Результат загрузки

- **Оригинал** (`.jpg`/`.png`) — уменьшен до 1200px, сжат (JPG — качество 75).
- **WebP-копия** (`.webp`) — из уменьшенной копии, качество 82.
- **Имя** — SEO-транслит.

## 3. Вывод изображений

### 3.1. PHP — `renderPicture()`

**Файл:** `includes/helpers.php`

Формирует `<picture>`: `<source type="image/webp">` + `<img>` fallback. Добавляет `width`/`height` (CLS = 0), `loading="lazy"` (кроме логотипа), логотипу — `fetchpriority="high"` (LCP).

**Пример:**

    <?= renderPicture('/uploads/example.jpg', 'Описание', 400, 400) ?>

    <picture>
      <source type="image/webp" srcset="/uploads/example.webp">
      <img src="/uploads/example.jpg" alt="Описание" width="400" height="400" loading="lazy">
    </picture>

### 3.2. JS — `buildPicture()`

**Файл:** `js/script.js`

Аналог `renderPicture()` для динамической подгрузки (корзина, каталог через fetch).

### 3.3. Fallback

- Браузеры без WebP (старые Safari, IE) — получают оригинал (`.jpg`/`.png`).
- Браузеры с WebP — получают `.webp` (меньше вес).

### 3.4. OG и Schema.org

- **OG-теги** (`og:image`) и **Schema.org** (`Product.image`, `WebPage.image`) — на **JPEG** (fallback).
- **11.11.2026:** для `WebPage.image` (произвольные страницы) используется WebP, если он есть.
- Причина: не все соцсети и AI-агенты корректно обрабатывают WebP.

## 4. SEO-переименование старых картинок (`rename-all-images.php`)

**Назначение:** одноразовый скрипт для переименования старых картинок в SEO-имена.

**Когда запускать:** после внедрения транслитерации в `upload.php`, если в `/uploads/` остались «мусорные» имена (`IMG_1234.jpg`, `photo.png`, кириллица).

**Что делает:** читает `/uploads/`, транслитерирует имена, переименовывает файлы (и `.webp`, если есть), обновляет ссылки в `data/*.json`.

**Запуск:** `https://ваш-сайт/rename-all-images.php` (одноразово).

> ⚠️ **После запуска — удалить скрипт с сервера.** Иначе любой сможет его запустить.

## 5. Оптимизация старых изображений

### 5.1. `scripts/optimize-uploads.php` (актуально на 11.11.2026)

**Назначение:** принудительная оптимизация старых файлов в `/uploads/`.

**Что делает:**
- Создаёт/пересоздаёт `.webp` из уменьшенной копии (макс. 1200px).
- Ужимает JPG-оригиналы (качество 75, макс. 1200px).

**Запуск:** `php scripts/optimize-uploads.php` (из корня проекта).

**Когда запускать:** после обновления до версии 2.5, если в `/uploads/` остались тяжёлые JPG/PNG без WebP.

### 5.2. `batch-webp.php` (исторический)

**Назначение:** одноразовый скрипт для конвертации старых картинок в WebP (до появления `scripts/optimize-uploads.php`).

**Что делал:** читал `/uploads/`, создавал `.webp` (качество 82), удалял WebP, если он больше оригинала.

**Запуск:** `https://ваш-сайт/batch-webp.php` (одноразово).

> ⚠️ **После запуска — удалить скрипт с сервера.**

> 💡 Для старых файлов теперь используйте `scripts/optimize-uploads.php` — он и WebP создаёт, и JPG ужимает.

## 6. Оптимизация PageSpeed (изображения)

| Что | Экономия |
|-----|----------|
| WebP для всех изображений | −32% размера |
| Логотип: `fetchpriority="high"` + `width`/`height` | LCP ↓, CLS = 0 |
| Логотип сжат (50 КБ → 16 КБ) | −34 КБ |
| `<picture>` с WebP + fallback | Совместимость + скорость |

**Результат:** CSS-блокировка снизилась с 1960 мс до ~600 мс (частично за счёт WebP).

**Осталось (низкий приоритет):** LCP ~2 сек — из-за окна 18+ (юридический компромисс).
