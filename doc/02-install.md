# 02. Установка и первоначальная настройка

**Проект:** AmanitaCMS · **Версия CMS:** 2.5 · **Актуально на:** 3 ноября 2026

**Демонстрационные сайты:** `muhomor.spb.ru`, `amanitalove.ru`

---

## 1. Требования к хостингу

| Компонент | Требование |
|-----------|-----------|
| PHP | 7.1+ (рекомендуется 7.4+) |
| Веб-сервер | Apache или LiteSpeed с `mod_rewrite`, `mod_headers`, `mod_deflate`, `mod_expires` |
| GD (php-gd) с WebP | Для авто-конвертации изображений |
| ZipArchive | Для резервного копирования |
| Права на запись | `/data/` и `/uploads/` |
| SMTP | Для отправки почты (порт 587, STARTTLS) |

**Текущий хостинг:** DirectAdmin, Windows, PHP 7.1, LiteSpeed, гипервизор `ha005`. <!-- БЫЛО: пути W:\domains\... -->

> ⚠️ **Внимание:** на Windows-хостинге `rename()` не атомарен — поэтому счётчик защищён через `flock()` (см. `01-architecture.md`, п. 5.10).

---

## 2. Быстрая установка

1. **Скопируйте файлы** в корень сайта (FTP/файловый менеджер хостинга).
2. **Проверьте `.htaccess`** в корне сайта — он должен быть на месте.
3. **Проверьте `/uploads/.htaccess`** — создан (запрет исполнения PHP).
4. **Проверьте `/includes/.htaccess`** — создан (защита includes).
5. **Установите права:**
   `chmod -R 755 data uploads`
6. **Откройте сайт** в браузере — должна загрузиться главная страница.

## 3. Первоначальная настройка

### 3.1. Первый вход в админку

1. Откройте `https://ваш-сайт/admin.php`.
2. **Логин:** `admin`
3. **Пароль:** `secret123`

> ⚠️ Дефолтный пароль **активен только до первой смены**. Смените сразу!

### 3.2. Смена пароля администратора

1. В админке → «⚙️ Настройки» → «🔐 Смена пароля».
2. Введите старый пароль (`secret123`), новый пароль (дважды).
3. Сохраните.

> ⚠️ **Пароль нельзя восстановить** — хранится только bcrypt-хеш. **Сохраните новый пароль в менеджере паролей** (Bitwarden, 1Password, KeePass). Если забудете — см. `03-admin.md` (восстановление пароля).

### 3.3. Заполнение настроек сайта

В «⚙️ Настройки» заполните:

| Поле | Что вписать |
|------|-------------|
| `site_name` | Короткое название (например, «Мой сайт») |
| `site_seo_title` | Длинный title для `<title>` (например, «AmanitaCMS — сушёные мухоморы с доставкой») |
| Контакты | Телефон, email, адрес |
| Соцсети | TG, VK, YouTube, MAX |
| Логотип | Загрузить через админку |
| Favicon | Загрузить через админку |
| GA4 ID | `G-XXXXXXXXXX` (ваш идентификатор) |
| Яндекс.Метрика ID | Оставить пустым, пока не заработает (см. `08-analytics.md`) |

### 3.4. Настройка почты

1. Откройте `includes/mail-config.php` (через FTP/файловый менеджер).
2. Заполните SMTP-параметры:

       'host'       => 'mail.example.com',
       'port'       => 587,
       'encryption' => 'tls',           // STARTTLS
       'username'   => 'noreply@example.com',
       'password'   => 'ВАШ_ПАРОЛЬ',
       'from_email' => 'noreply@example.com',
       'from_name'  => 'AmanitaCMS',
       'admin_email'=> 'admin@example.com',

3. Сохраните.
4. Проверьте: оформите тестовый заказ → должно прийти письмо на `admin_email`.
5. Шаблоны писем — в `includes/email-templates.php` (можно менять тексты).

> ⚠️ **Пароли хранятся в `mail-config.php`** — не выкладывайте этот файл в публичный доступ и не коммитьте в GitHub.

### 3.5. Первый бэкап

1. В админке → «⚙️ Настройки» → «📦 Резервное копирование».
2. Нажмите «📦 Скачать резервную копию».
3. Скачается ZIP `<домен>-backup-YYYY-MM-DD-HHMMSS.zip`.
4. **Сохраните архив в двух местах:** локально + в облаке.
5. **Не храните бэкап только на сервере** — при сбое хостинга он пропадёт.

## 4. Добавление контента

Все разделы управляются через админку:

| Раздел | Что можно делать |
|--------|-----------------|
| Товары | Добавить, редактировать, удалить, задать `seo_title`, цену, состав |
| Блог | Статьи с HTML-редактором Summernote, `slug`, метатеги |
| Новости | Аналогично блогу |
| Акции | Промо-страницы с пагинацией |
| FAQ | Вопросы-ответы (Schema.org FAQPage) |
| Отзывы | Модерация: `status: 0` → «✅ Опубликовать» → `status: 1` |
| Заказы | Просмотр, смена статуса, удаление |
| Настройки | SEO, контакты, соцсети, пароль, GA4, Метрика, бэкап |

**Отзывы:**
- Через админку — без ограничений.
- Через форму на сайте — с модерацией (`status: 0`).
- Модерация: список сортируется, неопубликованные сверху с бейджем «🆕 Новый».

## 5. Работа с изображениями

### 5.1. Автоматическая WebP-конвертация

При загрузке через админку (`upload.php`):
- Проверка MIME + `getimagesize()`.
- Транслитерация кириллицы в имени файла.
- Проверка на дубликаты.
- Создание `.webp`-копии (качество 82), если GD с WebP.
- Если WebP больше оригинала — удаляется.

**Результат:** на сайте отдаётся WebP через `<picture>`, для старых браузеров — оригинал.

### 5.2. Старые изображения

Если картинки загружены до внедрения WebP:
- `rename-all-images.php` — одноразово переименовывает в SEO-имена (латиница, дефисы).
- `batch-webp.php` — одноразово конвертирует в WebP.

> ⚠️ **Запускать только один раз.** После — удалить скрипты с сервера.

### 5.3. Если GD/WebP недоступны

Сайт работает на оригиналах. WebP-копии не создаются, `<picture>` отдаёт JPEG/PNG. Функциональность не страдает, но PageSpeed будет хуже.

## 6. Перенос на другой домен

1. Скопируйте все файлы на новый хостинг.
2. Скопируйте `/data/` и `/uploads/` (с содержимым).
3. Проверьте `.htaccess` в корне, `/uploads/.htaccess`, `/includes/.htaccess`.
4. `SITE_URL` определится автоматически (на основе протокола и `HTTP_HOST`).
5. Зайдите в админку → «⚙️ Настройки» → сохраните настройки (обновит `robots.txt`).
6. **Проверьте почту:** `includes/mail-config.php` — SMTP-хост может отличаться на новом хостинге. Обновите, если нужно.
7. **Проверьте sitemap:** откройте `/sitemap.xml` — должен отдаваться корректно.
8. **Проверьте 404:** откройте любой несуществующий URL — должен вернуть 404 (не 200).
9. **Проверьте редиректы:** HTTP → HTTPS, WWW → без WWW (301).
10. **Сделайте бэкап** на новом месте.

---

## 7. Обновление файлов (FTP)

> ⚠️ **Важно:** при обновлении файлов через FTP **переподключайтесь** — FTP-клиент может не видеть новые файлы.

**Порядок:**
1. Скачайте бэкап через `backup.php` (перед обновлением).
2. Загрузите новые файлы.
3. **Не перезаписывайте** `data/settings.json` (там `admin_password_hash` и настройки).
4. **Не перезаписывайте** `includes/mail-config.php` (там SMTP-пароли).
5. **Не удаляйте** `tailwind-output.css` (внешний файл, инлайн ломал вёрстку).
6. Проверьте сайт и админку.

## 8. Типичные проблемы при установке

| Проблема | Причина | Решение |
|----------|---------|---------|
| Белый экран | Ошибка PHP | Включить `display_errors` в `php.ini` или проверить лог хостинга |
| 500 Internal Server Error | Ошибка в `.htaccess` | Проверить синтаксис, закомментировать подозрительные строки |
| `sitemap.xml` не открывается | `MultiViews` в Apache | Добавить `Options -MultiViews` в `.htaccess` |
| Картинки не конвертируются в WebP | Нет GD/WebP | Установить `php-gd` с WebP на хостинге |
| Письма не приходят | SMTP-настройки | Проверить `includes/mail-config.php`, логи хостинга |
| Письма в спаме | Проблема получателя | Сменить получателя (например, на Яндекс) |
| Счётчик сбрасывается | Race condition | Проверить `counter.log`, убедиться, что `flock()` работает |
| Пароль забыт | bcrypt-хеш | См. `03-admin.md` |
| Иконки белые | Tailwind arbitrary values | Пересборка `tailwind-output.css` (см. `11-roadmap.md`) |

## 10. Документация (сборка HTML) <!-- НОВОЕ -->

Для лендинга `amanitacms.ru` документация из MD конвертируется в HTML скриптом `build_docs.py`.

**Требования:**
- Python 3.7+
- `pip install markdown`

**Запуск (из корня проекта):**

    python build_docs.py

**Результат:**
- `doc/*.html` — HTML-страницы документации.
- `doc/index.html` — оглавление.
- `doc/assets/docs.css` — стили (создаётся один раз, потом можно править).

**Важно:** запускать из корня проекта (где лежат `doc/` и `build_docs.py`). Если запустить из другого места — создаст папки там.

**Обновление:** после правки MD-файлов — просто перезапустить скрипт. HTML перезапишется, CSS останется.
