# 14. Перенос проекта в новый чат

**Проект:** AmanitaCMS · **Версия CMS:** 2.5 · **Актуально на:** 22 ноября 2026

**Демонстрационные сайты:** `muhomor.spb.ru`, `amanitalove.ru`

---

## 1. Обзор

Этот файл описывает, **как перенести контекст проекта в новый чат** (AI-ассистент) без потери информации.

**Проблема:** чаты имеют лимит токенов. Когда лимит близок — нужно начать новый чат, но сохранить контекст.

**Решение (22.11.2026):** нарезка файлов на части (`bundle_cut.py`) + `manifest.json` с `sha256` + склейка с проверкой (`bundle_merge.py`) + промт-шаблон (раздел 3). Правило «получено» — по `manifest.json`, а не «сообщение дошло» (см. `bundle_rules.md`).

---

## 2. Что передавать в новый чат

### 2.1. Минимальный набор

- **Нарезанные части** (`parts/<file>_partNN<ext>.txt`) + **`parts/manifest.json`**.
- **`bundle_rules.md`** — правила работы с частями.
- **`13-rules.md`** — общие правила (обязательно).
- **`01-architecture.md`** — общее состояние.
- **`11-roadmap.md`** — что сделано, что дальше.

### 2.2. Полный набор

- **Все части** + `parts/manifest.json`.
- **`bundle_rules.md`**, **`13-rules.md`**.
- **Все файлы `doc/`** — полная документация.
- **`README.md`** — краткое описание.

### 2.3. Что НЕ передавать

- **Пароли** (`admin_password_hash`, SMTP-пароль) — секреты.
- **Изображения** (`/uploads/*`) — большой объём.
- **Шрифты** (`/fonts/*`) — большой объём.
- **Библиотеки** (`/js/jquery`, `/js/summernote`) — не нужны для контекста.
- **`tailwind-output.css`** — генерируется, большой.
- **`doc/*.html`** — сгенерированные файлы (исходники в MD).

## 4. Что делать после отправки промта

1. **Дождитесь ответа** — новый чат должен подтвердить, что понял контекст и правила.
2. **Проверьте**, что он **не предлагает** удалить комментарии, заменить JSON на MySQL, инлайнить `tailwind-output.css` и т.п.
3. **Проверьте**, что он **различает** форматы: документация → markdown, код → как есть (не путает `.php` и `.md`).
4. **Задайте задачу** — пошагово (правило 4).
5. **Следите за соблюдением правил** — если новый чат их нарушает, напомните.

## 5. Как нарезать и склеить бандл (актуально на 22.11.2026)

**Нарезка** (перед отправкой):

    python bundle_cut.py --config bundle_config.json

Результат: в `parts/` — файлы `<file>_partNN<ext>.txt` (без маркеров) + `parts/manifest.json` с `sha256` каждой части и целого файла.

**Склейка** (после получения всех частей):

    python bundle_merge.py --manifest parts/manifest.json --out-dir restored

Скрипт проверяет наличие всех частей и `sha256` каждой. Если часть отсутствует или `sha256` не совпал — падает с ошибкой, файл не собирается.

**Правило:** «получено» = все части на диске + `merge` прошёл без ошибок. Подробнее — `bundle_rules.md`.

**Исторический механизм:** `bundle_project.py` (один файл `bundle/project_bundle.txt`, ~413 КБ) — заменён на нарезку/склейку.

## 6. Альтернатива — передача файлов по одному

Если части слишком большие (или нужно передать только часть):

1. **`README.md`** (краткое описание).
2. **`01-architecture.md`** (общее состояние).
3. **`13-rules.md`** (правила).
4. **Конкретные файлы** для задачи (например, `admin.php`, `admin.js`).
5. **`11-roadmap.md`** (что дальше).

**Минус:** новый чат не увидит весь код, только переданное.
**Плюс:** меньше токенов.

## 8. Частые ошибки при переносе

| Ошибка | Последствие | Как избежать |
|--------|-------------|--------------|
| Передать бандл **с** `admin_password_hash` | Утечка хеша | Проверить бандл перед отправкой |
| Не передать `13-rules.md` | Новый чат удаляет комментарии | Всегда передавать правила |
| Передать **весь** код (включая `tailwind-output.css`) | Лимит токенов | Использовать нарезку |
| Не сформулировать задачу | Новый чат «плывёт» | Вписать задачу в промт |
| Не проверить ответ | Новый чат ломает архитектуру | Проверять первые ответы |
| Новый чат отдаёт код в markdown-блоке | Путаница `.php` vs `.md` | Напомнить правило 2 |
| «Получено» без `merge` | Часть потеряна, файл битый | «Получено» = merge прошёл (sha256) |
