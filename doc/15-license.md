## 1. Лицензия

**Тип лицензии:** Proprietary (проприетарная), с публичным исходным кодом. Лицензия не менялась — Proprietary с самого начала.

**Права:** все права на AmanitaCMS принадлежат владельцу проекта.

**Что это значит:**
- Исходный код **публично доступен** на GitHub (`KonstantinFromRussia/amanitacms`), но **не является** open source в классическом смысле (лицензия не разрешает свободное коммерческое использование без согласования).
- Копирование, распространение, модификация для **коммерческих целей** без разрешения владельца — **запрещены**.
- Для **личного использования и изучения** — код доступен.
- Демо-сайты (`muhomor.spb.ru`, `amanitalove.ru`) — примеры работающих проектов; их контент и права регулируются отдельно (см. раздел 2).

## 2. Права на контент

### 2.1. Тексты

- Тексты статей, описаний товаров, FAQ, страницы «О нас» — **собственность владельца** (или владельцев демо-сайтов, если размещены на них).
- 3 SEO-лонгрида для блога — написаны и переданы владельцу.
- HTML-шаблон описания товара — собственность владельца.

### 2.2. Изображения

- Фотографии товаров, логотип, фото со страницы «О нас» — **собственность владельца** (или владельцев демо-сайтов).
- SEO-имена файлов (`example-100g.jpg` и т.п.) — результат работы `rename-all-images.php`, права не меняются.

### 2.3. Иконки и шрифты

- **Inline-SVG** (иконки соцсетей, интерфейса) — созданы для проекта, права у владельца.
- **Шрифт Roboto** — свободная лицензия (Apache 2.0 / SIL Open Font License), можно использовать без ограничений.
- **Summernote** — MIT License (свободная).
- **jQuery** — MIT License (свободная).
- **PHPMailer** — LGPL 2.1 (свободная, но с ограничениями для проприетарных проектов — проверьте совместимость).

## 4. Данные пользователей

### 4.1. Какие данные собираются

- **Заказы:** имя, телефон, email, адрес доставки, комментарий, состав заказа.
- **Отзывы:** имя, текст отзыва (email — опционально).
- **Счётчик:** cookie `visitor_id` (анонимный идентификатор), IP-адрес (для фильтрации ботов).
- **Аналитика:** GA4 и Яндекс.Метрика (анонимные данные о визитах).

### 4.2. Где хранятся

- **Заказы:** `data/orders.json`.
- **Отзывы:** `data/reviews.json`.
- **Счётчик:** `data/counter.json`, `data/counter.log`.
- **Аналитика:** на серверах Google (GA4) и Яндекса (Метрика).

### 4.3. Кто имеет доступ

- **Владелец сайта** (через админку).
- **Хостинг** (технически, через файловую систему).
- **Google** (GA4) и **Яндекс** (Метрика) — анонимные данные.

### 4.4. Защита данных

- `/data/` защищён `.htaccess` (403).
- `mail-config.php` защищён `.htaccess`.
- Пароль админа — bcrypt-хеш.
- Бэкапы — ZIP, хранятся у владельца.

### 4.5. Что НЕ делается

- **Нет** передачи данных третьим лицам (кроме GA4/Метрики — анонимно).
- **Нет** продажи данных.
- **Нет** массовых рассылок без согласия.

## 5. Возрастное ограничение 18+

AmanitaCMS — универсальная CMS. Если на её базе продаются товары, требующие возрастного ограничения, это **ответственность владельца сайта**.

**Что сделано в демо-сайтах:**
- Окно 18+ при входе на сайт.
- Подтверждение возраста через `localStorage`.
- Юридический компромисс: LCP ~2 сек (окно перекрывает контент).

**Рекомендация:** проконсультируйтесь с юристом по поводу:
- Обязательности окна 18+ (в РФ — для некоторых товаров).
- Дисклеймеров на страницах товаров («не является лекарством», «проконсультируйтесь с врачом»).
- Условий доставки и возврата.

## 6. Отказ от ответственности

**Владелец проекта не несёт ответственности:**
- За неправильное использование продукта, продаваемого на демо-сайтах.
- За последствия самолечения.
- За действия третьих лиц (хакеры, сканеры).
- За сбои хостинга (LiteSpeed, DirectAdmin, ha005).

**Владелец прилагает усилия:**
- Для защиты данных (`.htaccess`, bcrypt, `flock()`).
- Для корректной работы сайта (тестирование, бэкапы).
- Для соблюдения законов РФ (18+, дисклеймеры).

## 7. Бэкапы и восстановление

### 7.1. Кто отвечает

- **Владелец сайта** — за регулярность бэкапов.
- **Хостинг** — за сохранность сервера (но **не** за данные сайта).

### 7.2. Что делать при потере данных

1. **Проверить бэкапы** (ZIP-архивы).
2. **Восстановить** из последнего бэкапа.
3. **Проверить** сайт и админку.
4. **Сделать новый бэкап**.

### 7.3. Рекомендации

- **Бэкап раз в неделю** (минимум).
- **Перед крупными изменениями** — обязательно.
- **Хранить в двух местах** (локально + облако).
- **Проверять бэкапы** (открывается ли ZIP, целы ли файлы).

**Подробнее** — см. `02-install.md`, п. 7.
