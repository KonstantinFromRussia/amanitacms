**Проект:** AmanitaCMS · **Версия CMS:** 2.5 · **Актуально на:** 3 ноября 2026

**Демонстрационные сайты:** `muhomor.spb.ru`, `amanitalove.ru`

## 1. Обзор

В проекте есть три Python-скрипта:

| Скрипт | Расположение | Назначение |
|--------|-------------|-----------|
| `customize_cms.py` | `script1/` | Уникализация CMS (замена классов, удаление комментариев, перемешивание блоков) |
| `bundle_project.py` | `script2/` | Сборка значимых файлов в один текстовый файл для переноса в чат |
| `build_docs.py` | корень | Конвертация MD-документации в HTML для лендинга <!-- НОВОЕ --> |

Все скрипты — **вспомогательные**, не влияют на работу сайта напрямую. Запускаются вручную на локальной машине.

## 2. `customize_cms.py` — уникализация CMS

### 2.1. Назначение

Копирует CMS, **заменяет CSS-классы**, **удаляет HTML/CSS-комментарии**, **перемешивает блоки внутри `<main>`**. Позволяет создавать уникальные версии под разные регионы/домены (например, `site-ekb.ru`, `site-nsk.ru`). <!-- БЫЛО: muhomor-ekb.ru, muhomor-nsk.ru -->

### 2.2. Расположение и требования

- **Файл:** `script1/customize_cms.py`
- **Требования:** Python 3.7+, PyYAML (`pip install -r script1/requirements.txt`).
- **Конфигурация:** `script1/config.yaml`.
- **Обёртка запуска:** `script1/custom.cmd` (для Windows).

### 2.3. Что делает

1. **Копирует** исходную CMS в новую директорию (указанную в `config.yaml`).
2. **Заменяет CSS-классы** — по словарю в `config.yaml` (например, `btn-primary` → `ekb-btn-primary`).
3. **Удаляет HTML/CSS-комментарии** (кроме тех, что в `skip_process`).
4. **Перемешивает блоки** внутри `<main>` — случайно, с фиксированным seed (для воспроизводимости).
5. **Пропускает** файлы из `skip_process` — не трогает их.

### 2.4. `skip_process` — критическое исправление (23.10)

**Проблема:** после кастомизации ломались админка и Summernote. Скрипт менял CSS-классы в `admin.php`, `admin.js`, `jquery`, `summernote` — и они переставали работать.

**Решение:** в `config.yaml` добавлен `skip_process` для:
- `admin.php`
- `admin.js`
- `jquery-3.6.0.min.js`
- `summernote/`

**Результат:** админка и Summernote работают корректно после кастомизации.

### 2.5. Запуск

**Dry-run** (проверка без записи):

    python customize_cms.py --dry-run --seed 12345

**Реальный запуск:**

    python customize_cms.py --seed 12345

**Параметры:**
- `--dry-run` — проверить, но не записывать.
- `--seed N` — фиксированный seed для воспроизводимости (одинаковый seed → одинаковый результат).
- `--prefix ekb` — префикс для замены классов (roadmap, см. 2.7).

**Результат последнего dry-run:** 1892 замены, 0 ошибок.

### 2.6. Что НЕ делает

- **Не меняет** структуру `data/*.json`.
- **Не трогает** `tailwind-output.css` (не пересобирает).
- **Не трогает** `admin_password_hash`.
- **Не трогает** `mail-config.php` (если в `skip_process`).
- **Не запускает** никаких серверных скриптов.
- **Не трогает** `build_docs.py` и `doc/*.md` (документация не участвует в уникализации). <!-- НОВОЕ -->

### 2.7. Roadmap

- [ ] **`--prefix ekb`** — уникализация под Екатеринбург (`site-ekb.ru`).
- [ ] **`--prefix nsk`** — уникализация под Новосибирск (`site-nsk.ru`).
- [ ] **Автоматическая пересборка `tailwind-output.css`** — после замены классов (сейчас нужно вручную).
- [ ] **Поддержка `skip_process` для новых файлов** — по мере необходимости.

## 3. `bundle_project.py` — сборка бандла

### 3.1. Назначение

Собирает **значимые файлы** проекта в один текстовый файл (`bundle/project_bundle.txt`) для **переноса в чат** (например, для продолжения работы с Deepseek). Автоматически **чистит секреты** (`admin_password_hash`, `admin_login`).

### 3.2. Расположение и требования

- **Файл:** `script2/bundle_project.py`
- **Требования:** Python 3.7+.
- **Результат:** `bundle/project_bundle.txt` (~413 КБ).

### 3.3. Что включает

**Значимые файлы:**
- Все `.php` в корне (`index.php`, `catalog.php`, ..., `admin.php`, `api.php`).
- Все `.php` в `/includes/`.
- Все `.json` в `/data/` (**кроме** `settings.json` в части секретов — см. 3.4).
- `.htaccess` (корень, `/uploads/`, `/includes/`).
- `robots.php`, `sitemap.php`, `llms.txt`.
- `.well-known/ai-catalog.json`, `.well-known/ard.json`.
- `README.md`.
- Скрипты (`customize_cms.py`, `config.yaml`, `bundle_project.py`).
- `build_docs.py` (если есть). <!-- НОВОЕ -->

### 3.4. Что чистит

- **`admin_password_hash`** — удаляется из `settings.json` перед сборкой.
- **`admin_login`** — удаляется из `settings.json` перед сборкой.
- **Пароли SMTP** — если в `mail-config.php` есть пароль, он **не должен** попадать в бандл (проверьте, что `mail-config.php` в исключениях, или пароль замаскирован).

**Результат:** бандл можно безопасно передавать в чат (без секретов).

### 3.5. Запуск

    python bundle_project.py

**Результат:** `bundle/project_bundle.txt` (~413 КБ).

### 3.6. Что НЕ включает

- Изображения (`/uploads/*.jpg`, `*.webp`) — слишком большой объём.
- Шрифты (`/fonts/*.woff2`).
- Библиотеки (`/js/jquery-3.6.0.min.js`, `/js/summernote/*`).
- `tailwind-output.css` (слишком большой, генерируется).
- `.git/`, `node_modules/`, временные файлы.
- `doc/*.html` (сгенерированные файлы — не нужны в бандле). <!-- НОВОЕ -->

### 3.7. Зачем нужен

- **Перенос в новый чат** — одним файлом, без потери контекста.
- **Резервная копия кода** — текстовый файл, можно хранить в Git.
- **Аудит** — быстро посмотреть все значимые файлы.

## 4. Как использовать вместе

**Сценарий: уникализация под новый регион + перенос в чат**

1. Запустить `customize_cms.py --seed 12345` → получить уникальную копию CMS.
2. Проверить dry-run (1892 замены, 0 ошибок).
3. Запустить `bundle_project.py` → получить `project_bundle.txt`.
4. Передать бандл в чат (Deepseek) для продолжения работы.
5. Развернуть уникальную копию на новом домене.
6. Настроить `mail-config.php` (свой SMTP).
7. Настроить GA4/Метрику (свои ID).
8. Сделать бэкап.
