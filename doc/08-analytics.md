## 1. Обзор

В проекте используются (или планируются) три инструмента аналитики:

| Инструмент | Статус | Назначение |
|------------|--------|-----------|
| **Google Analytics 4 (GA4)** | ✅ Подключён | Основная аналитика (трафик, конверсии, поведение) |
| **Google Tag Manager (GTM)** | ⚠️ Не грузится напрямую | Контейнер тегов (обход через hosts) |
| **Яндекс.Метрика** | ❌ Не подключена | Аналитика для РФ-аудитории (ждём восстановления ДЦ) |

## 2. Google Analytics 4 (GA4)

### 2.1. ID

**GA4 ID:** `G-LSRBZ45NLB`

**Где хранится:** в `data/settings.json` (поле `ga4_id` или аналогичное — вписывается через админку).

### 2.2. Подключение

- В админке → «⚙️ Настройки» → поле «GA4 ID» → вписать `G-LSRBZ45NLB`.
- Код GA4 выводится в `includes/head.php` (или `footer.php` — по реализации).
- **Статус:** подключён и работает.

### 2.3. Проверка

1. Откройте сайт в браузере.
2. Откройте `https://analytics.google.com` → выберите ресурс `G-LSRBZ45NLB`.
3. Раздел «Отчёты» → «В реальном времени» — должны появиться ваши визиты.
4. Если визитов нет — проверьте:
   - GA4 ID в админке.
   - Код GA4 в исходном коде страницы (`Ctrl+U` → поиск `G-LSRBZ45NLB`).
   - Блокировщики рекламы (могут блокировать GA4).

## 3. Google Tag Manager (GTM)

### 3.1. Статус

**GTM не грузится напрямую.** Причина — ошибка `ERR_NAME_NOT_RESOLVED` для `fonts.googleapis.com` (и, возможно, для других доменов Google).

### 3.2. Обход

**Решение:** добавление IP в файл `hosts` на **локальной машине** (не на сервере).

**Шаги (Windows):**
1. Откройте `C:\Windows\System32\drivers\etc\hosts` (от имени администратора).
2. Добавьте строку:

       142.250.74.163 fonts.googleapis.com

3. Сохраните.
4. Сбросьте DNS-кеш: `ipconfig /flushdns` (в командной строке от администратора).
5. Перезагрузите браузер.

**Результат:** GTM (и Google Fonts, если используются) начнут грузиться на вашей машине.

> ⚠️ **Это обход только для локальной машины.** На сервере и у посетителей GTM может не грузиться (проблема DNS на стороне хостинга/провайдера).

### 3.3. Нужен ли GTM?

**Вопрос открытый.** GA4 подключён напрямую (без GTM). Если GTM не нужен для дополнительных тегов (пиксели, события, A/B-тесты) — можно **не подключать**. Если нужен — решать проблему с DNS на уровне хостинга (обращение в поддержку).

## 4. Яндекс.Метрика

### 4.1. Статус

**НЕ подключена.** Причина — дата-центры Яндекса не восстановились, статистика не грузится. Поле для ID в админке **готово**.

### 4.2. Что сделано

- В админке → «⚙️ Настройки» → поле «Яндекс.Метрика ID» — готово.
- Код Метрики **не выводится** (ID пустой).
- **Ждём восстановления ДЦ Яндекса.**

### 4.3. Когда заработает

1. Получите ID счётчика в Яндекс.Метрике (`https://metrika.yandex.ru`).
2. В админке → «⚙️ Настройки» → поле «Яндекс.Метрика ID» → вписать ID.
3. Сохранить.
4. Проверить: откройте сайт → в Метрике «Реaltime» — должны появиться визиты.
5. Если визитов нет — проверьте код Метрики в исходном коде страницы (`Ctrl+U` → поиск `ym(` или `metrika`).

### 4.4. Альтернативы (если ДЦ Яндекса не восстановятся)

- **Яндекс.Метрика через прокси** — не рекомендуется (нарушение ToS).
- **Самостоятельная аналитика** — `counter.json` (счётчик посетителей), но это не полноценная аналитика.
- **Другие инструменты** — Plausible, Matomo (требуют установки).

**Рекомендация:** ждать восстановления ДЦ Яндекса. Пока — GA4 достаточно.

## 5. Счётчик посетителей (внутренний)

Помимо внешних инструментов, в проекте есть **внутренний счётчик** (`includes/counter.php`).

**Что считает:**
- Уникальных посетителей (cookie `visitor_id` на 1 год).
- Фильтры: админы, боты, API/AJAX, не-GET.
- Хранение: `data/counter.json`.
- Вывод: в футере через `getVisitorCount()`.

**Зачем:**
- Быстрый взгляд на трафик без внешних инструментов.
- Независимость от GA4/Метрики.

**Подробнее** — см. `01-architecture.md`, п. 5.10.
