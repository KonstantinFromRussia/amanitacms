## 2. Настройки SMTP

**Файл:** `includes/mail-config.php`

**Параметры (пример):**

    'host'        => 'mail.example.com',
    'port'        => 587,
    'encryption'  => 'tls',                        // STARTTLS
    'username'    => 'noreply@example.com',
    'password'    => 'ВАШ_ПАРОЛЬ',
    'from_email'  => 'noreply@example.com',
    'from_name'   => 'AmanitaCMS',
    'admin_email' => 'admin@example.com',

> ⚠️ **Пароль хранится в `mail-config.php`** — не выкладывайте файл в публичный доступ, не коммитьте в GitHub, не перезаписывайте при обновлениях.

**Почему Яндекс для админских уведомлений:**
- `pcweb@mail.ru` — письма попадают в спам (проблема Mail.ru, не наша).
- `admin@example.com` — тестовый ящик, письма доходят.
- Для боевого режима можно сменить на любой удобный ящик (Яндекс, Gmail), но **не** на `pcweb@mail.ru`.

## 3. Шаблоны писем

**Файл:** `includes/email-templates.php`

**Текущие уведомления:**
- Новый заказ (админу).
- Новый отзыв (админу).
- Смена статуса заказа (админу; клиенту — в Roadmap).

**Как работают:**
- Обёртка над PHPMailer — `includes/mailer.php`.
- Вызов из `api.php` при соответствующих действиях.
- Шаблоны — HTML-письма с подстановкой переменных (имя клиента, номер заказа, состав, сумма).

**Как редактировать шаблоны:**
1. Откройте `includes/email-templates.php`.
2. Найдите нужный шаблон (например, `getNewOrderTemplate()`).
3. Отредактируйте HTML и текстовые переменные.
4. Сохраните.
5. Проверьте: оформите тестовый заказ → должно прийти письмо с новым текстом.

## 4. Библиотека PHPMailer

**Расположение:** `includes/PHPMailer/`
**Файлы:** `PHPMailer.php`, `SMTP.php`, `Exception.php`.

**Подключение:** через `includes/mailer.php` (обёртка).

**Зачем PHPMailer, а не `mail()`:**
- `mail()` на Windows-хостинге часто не работает или попадает в спам.
- SMTP + STARTTLS + авторизация — надёжнее.
- PHPMailer поддерживает HTML-письма, вложения, кодировки.

## 5. Проверка работы почты

**Шаги:**

1. Оформите **тестовый заказ** через корзину на сайте.
2. Проверьте ящик `admin@example.com` — должно прийти письмо «Новый заказ».
3. Отправьте **тестовый отзыв** через форму на странице товара.
4. Проверьте ящик — должно прийти письмо «Новый отзыв».
5. Смените статус тестового заказа в админке.
6. Проверьте ящик — должно прийти письмо «Смена статуса».

**Если письма не приходят:**
- Проверьте `includes/mail-config.php` (хост, порт, логин, пароль).
- Проверьте лог хостинга (ошибки SMTP).
- Проверьте, не попали ли письма в спам.
- Проверьте, что `noreply@example.com` не заблокирован (обратитесь в поддержку хостинга).

## 6. Известные проблемы и обходные пути

### 6.1. `pcweb@mail.ru` — письма в спаме

**Причина:** Mail.ru фильтрует письма с некоторых SMTP-серверов.

**Решение:**
- Использовать Яндекс для админских уведомлений.
- Для клиентских уведомлений — тоже Яндекс или Gmail.

### 6.2. Блокировка аккаунта на уровне хостинга

**Причина:** аккаунт `noreply@` попал в чёрный список на уровне хостинга (ошибка `550 User account is not allowed to send emails`).

**Решение:** обращение в поддержку хостинга (требуется root-доступ). Инженеры разблокировали аккаунт.

**Профилактика:**
- Не отправлять массовые рассылки с `noreply@`.
- Не использовать `noreply@` для тестов с подозрительным содержимым.
- Следить за логами SMTP.

### 6.3. Внешний SMTP (резервный вариант)

Если `mail.example.com` перестанет работать:

**Вариант 1 — Яндекс.Почта для домена:**
- Подключить домен к Яндекс.Почте.
- Создать ящик `noreply@ваш-домен`.
- В `includes/mail-config.php` изменить:
  - `host` → `smtp.yandex.ru`
  - `port` → `465`
  - `encryption` → `ssl`
  - `username` → `noreply@ваш-домен`
  - `password` → пароль от Яндекс-ящика (или app-password).

**Вариант 2 — Gmail:**
- Создать `noreply@gmail.com`.
- Включить двухфакторную аутентификацию.
- Создать app-password.
- В `includes/mail-config.php` изменить:
  - `host` → `smtp.gmail.com`
  - `port` → `587`
  - `encryption` → `tls`
  - `username` → `noreply@gmail.com`
  - `password` → app-password.

**Вариант 3 — смена хостинга:**
- Крайний вариант, если текущий хостинг не решает проблему с почтой.

> 💡 **Roadmap:** уведомления клиенту при смене статуса заказа — см. `11-roadmap.md` (высокий приоритет).

## 7. Безопасность

- **`mail-config.php` не доступен из браузера** — защищён `.htaccess` в `/includes/`.
- **Пароли не в публичных файлах** — только в `mail-config.php`.
- **Не коммитьте `mail-config.php` в GitHub** — добавьте в `.gitignore`.
- **Не отправляйте массовые рассылки** с `noreply@` — можно снова попасть в блокировку.
- **Не используйте `noreply@` для тестов** с подозрительным содержимым (спам-фильтры).
